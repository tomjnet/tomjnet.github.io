# Tomas Jimenez — portfolio website

Astro + Tailwind static site, deployed to GitHub Pages.

| Page | Content lives in |
|---|---|
| Home | `src/components/`, `src/data/site.ts` |
| Posts | the `website-info` repo (`contentRepo` in `src/data/site.ts`), rendered at build time |
| Research | the `website-info` repo, same as posts |
| Hobbies | `src/content/hobbies/*.md` |

Posts and research are fetched from the content repo during the build (`src/lib/content.ts`), so every page is
plain HTML that crawlers and link previews can read. Each post gets its own page at `/posts/<slug>/`.
Content changes show up on the next deploy: a push here, a manual run of the CI/CD workflow, or the daily rebuild.

## Develop

```bash
npm install
npm run dev
```

In dev, Posts and Research read from `website-info/` (a local copy of the content repo) if it exists.
To build from a local copy: `CONTENT_DIR=website-info npm run build`.

## Research status

Each paper's frontmatter has a `status`. Known values get a label and badge style from `RESEARCH_STATUS` in
`src/lib/content.ts`: `published`, `preprint` (shown as "Preprint / Study protocol"), `ongoing`, `idea`.
Any other value is shown as written.

## Scheduling a post

Give the post a future `date` in its frontmatter in the content repo, and push it as usual:

```yaml
---
title: "My next post"
date: 2026-11-02
---
```

Posts dated after today (UTC) are left out of the build: no page, no list entry, no sitemap entry.
`.github/workflows/daily-rebuild.yml` rebuilds and redeploys the site every day at 00:15 UTC, so the post goes
live on its date without any action. To preview scheduled posts locally, run with `INCLUDE_SCHEDULED=true`.

Note: the Markdown is still public in the content repo before its date. Scheduling only hides it from the site.

## Link preview image

`public/og-image.png` (1200x630) is generated by `npm run og`. It uses `public/images/headshot.jpg` when that
file exists. Re-run the script after changing the headshot, name or title.

## Content repo

Copy `website-info/` into a new public GitHub repo (default `tomjnet/website-info`). Its README explains how to add posts and research.

## Deploy

Push to `main`. `.github/workflows/ci-cd.yml` type-checks, builds and publishes to GitHub Pages. Pull requests run the same checks without deploying.
In the repo settings, go to Pages and set Source to **GitHub Actions**.
A repo named `<user>.github.io` is served at the root. Any other repo is served at `/<repo>/`, and the workflow sets that path automatically.
